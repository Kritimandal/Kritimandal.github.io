Case study · Sep 2024 – present

Health information systems at Nyaya Health Nepal

My day-to-day work is on a Bahmni electronic health record: extending it, upgrading the Odoo part of it, and connecting it to other systems. I am also on the team that delivered a provincial health dashboard.

Role
EHR Junior Developer. Joined as Associate Software Engineer
Organisation
Nyaya Health Nepal, Kathmandu
Systems
Bahmni: OpenMRS, OpenELIS, Odoo
Stack
Python, Django, PHP, JavaScript, Redis, Docker, Linux

This is production work for an employer. The code, screens and data are not public, so this page describes the work in words and does not include screenshots, figures or patient data.

01The platform

System I work on

Bahmni is an open-source hospital system that combines three applications: OpenMRS for clinical records, OpenELIS for the laboratory, and Odoo for billing and stock. Each has its own data model and API, and they exchange data with each other.

My work on it:

  • Extending and customising Bahmni's parts with Python, PHP and JavaScript.
  • Designing and maintaining the APIs and integrations between systems, using REST, JSON-RPC and XML-RPC.
  • Finding and fixing issues in the live system across Python and PHP code.

02Odoo 10 to 16

Built by me

Requirement. Custom features written for Odoo 10 had to keep working after the move to Odoo 16.

What I did. I migrated those custom features to Odoo 16 and tested each one after the move.

03Insurance claims

Built by me

Requirement. Billing in Odoo needed to work with patients' health insurance.

What I built. An insurance claim integration in Odoo with three parts:

  • an eligibility check for the patient's insurance,
  • claim submission,
  • a co-payment option for the share the patient pays.

04Karnali dashboard

Built with a team

Context. The health ministry of Karnali Province wanted the data from the province's hospitals in one dashboard.

What the team delivered. The Integrated Health Dashboard, a Django application that brings hospital data into one view. It covers:

  • patient registrations and patient visits,
  • bed occupancy,
  • gender and payment mix,
  • top diagnoses,
  • ward-wise data.

I was part of the development team that built it in Python and Django.

05Running it

  • Improved performance with Redis caching and by optimising SQL queries and stored procedures.
  • Deployed applications with Docker on Linux servers.
  • Worked through Git branches, pull requests and code review with the rest of the team.
